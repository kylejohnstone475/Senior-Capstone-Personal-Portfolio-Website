Project Management Plan

Case Study - Software Database

   The University of South Florida has contracted a team of software engineers to develop a software-tracking database system. It is required that educational institutions like the University of South Florida keep track of the different kinds of software used throughout the university system. The creation of the database will streamline the maintenance and tracking of this software. The university has asked that the database also keep track of components such as the type of software, the developer of the software, the versions of the software, licensing agreements, departments that use the software, the computers the software is installed on, installation dates, and any other relevant information pertaining to the software. This case study will outline the six steps of project management described in the Project Management Handbook that the engineering team will follow in order to successfully complete the project.

I. Initiation Phase

   The purpose of the initiation phase is to make several decisions and answer questions regarding the initiation of the project. It has already been determined that the software engineering team, nicknamed SET, will carry out the project. The software information needed for the project will be provided by USF departments and administrative units. The remainder of this section will answer the questions posed in the Project Management Handbook section on the initiation phase: Why this project? Is it feasible? Possible partners? Result outlook? What's outside the scope? (Baars, 2006, p. 1-2) Creating a software database will help organize the various software used across the entire organization. This will streamline software management for the university and meet certain requirements regarding software tracking. The project is feasible because the software that needs to be tracked is limited to software that is used within the university and is used for university functions. The IT department will have access to all the software already. Possible partners include the USF IT department, department heads, administrative heads, and university students. The final result should be a working database that can be used to access information on any software being used in any part of the university system. Once the implementation phase is finished, the system will continue to be updated and monitored to deal with bugs and any issues that may arise. Regarding scope, The project should not deal with tracking any software that is used outside of the university system. The database is only meant to log key information on software, and will not be used for any sort of surveillance or monitoring.

II. Definition Phase

   The definition phase addresses requirements and expectations associated with the project result and are specified clearly. The major requirement of the project is that the contracted team SET will create a database that keeps track of all software used across the university system. SET will work with the USF IT department, department heads, and administrative heads in order to gather information on the software used across the university. The Project Management Handbook states that several types of requirements must be established in this phase before the project can proceed: preconditions, functional requirements, operational requirements, and design limitations (Baars, 2006, p. 1-3). Regarding preconditions, employee and student privacy must be respected. Methods that would violate the privacy of students or employees during the process of gathering software for the database must be avoided. For functional requirements, the database should include all the information that is required to be tracked and must be modifiable assuming the software being used will change over time and will account for updates to any information or the software itself. The database should be able to keep track and monitor the various software used across the university in order to meet the operational requirements. Finally, design limitations revolve around privacy restrictions. The database cannot be used to monitor or surveil the actual use of software or be used to invade privacy in any way.

III. Design Phase

   Designs are created to help outline the development and implementation of the project (Baars, 2006, pp. 1-5 - 1-6). Designs will need to be created for time budgets, the information gathering process, and the development of the database. Gantt charts can be created to budget the time of individual tasks and processes of the work needed to be done for the project. Flowcharts can be created to outline the process of information gathering. Details can include the people to talk to and interact with and systems used for gathering information. It will be vital to create a flowchart diagram which outlines the process of creating the database. SET has decided and USF has agreed that the database software will be made in-house from scratch.

IV. Development Phase

   The purpose of the development phase is to determine everything that will be needed to develop the project (Baars, 2006, p. 1-6). Meetings are set up with IT and school officials to discuss discovery. Meetings will establish time frame, budget, how to gather required information for the database, and access to university information for the development team. It is decided that computer science undergraduates will be given internship opportunities to aid the development of the database software. A plan to begin developing the database software is created, how to incorporate university software information, and how to update software information when necessary - automatically or manually. SET team members and interns are assigned roles in the project, which include: leadership, software development, information gathering, and auxiliary intern roles.

V. Implementation Phase

   Implementation involves the construction of the actual project and begins when development establishes what must be accomplished (Baars, 2006, pp. 1-6 - 1-7). Software development and information gathering can proceed at the same time, but it is expected that software development will take much more time. Information gatherers will switch over to software development once all required information is obtained. Since the database software is being created in-house, SET will construct a manual for the database. A help desk will also be established as part of a new role at the university's IT department. These final processes will begin in the follow-up phase.

VI. Follow-Up Phase

   Once the implementation of the project is complete and the resulting product can be deployed, the follow-up phase can begin (Baars, 2006, pp. 1-7 - 1-8). The follow-up phase will technically be indefinite, as maintenance and assistance for the new database and software will be ongoing. One or more roles are created within the IT department to monitor, work on, and provide support for the database. The follow-up phase will 'conclude' when SET can fully hand over the maintenance of the database and software to the USF IT department.

   To summarize, this case study outlines the six steps of project management which the contracted team SET will follow in order to successfully complete the software-tracking database they were contracted for. The completion of the database will streamline software tracking and maintenance as well as meet certain requirements of educational institutions. It is important to note that, while following the project management plan is vital to the success of the project, game-time decisions may need to be made along the way in order to keep the project within scope and budget.
